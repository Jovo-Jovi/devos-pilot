#### Steps

- **S1 — Pure logic (`src/lib/supabase/staff-access.ts`, next to `decideStaffAccess`).**
  - `parseInviteLink(params: URLSearchParams): { tokenHash: string } | null` returns the token only
    when `type` is exactly `invite` and `token_hash` is non-empty. Any other `type` gives `null`
    (`recovery`, `signup`, `magiclink`, `email_change`, missing): OD-10 §3 has no recovery.
  - `decidePasswordAccess({ account, hasVerifiedFactor })` returns `"sign-in"` (no account),
    `"refused"` (the claim is not JSON `true`), `"mfa"` (a verified TOTP factor exists) or
    `"allowed"`, in that order. Setting a password serves the invitation only. Changing the password
    of an enrolled account is account management, which OD-10 excludes.
  - `checkNewPassword(password, confirmation)` returns `"mismatch"` when they differ, else `null`.
- **S2 — Confirm route (`src/app/[locale]/staff/auth/confirm/route.ts`, `GET` only).**
  - Unknown locale (`!isLocale`) → 404.
  - `parseInviteLink` gives `null` → redirect to `/{locale}/staff/sign-in?error=link`, with no Auth
    call.
  - Otherwise, `createStaffServerClient()` then `auth.verifyOtp({ type: "invite", token_hash })`. On
    error → the same `?error=link` redirect.
  - On success, `getUser()`. If the claim is not JSON `true`, `signOut()` and redirect to
    `?error=refused`. Otherwise redirect to `/{locale}/staff/password`.
  - Every response carries `Cache-Control: no-store`. No `Location` carries `token_hash`, and nothing
    logs the token (`SECURITY_MODEL.md` §3).
- **S3 — Password page (`/[locale]/staff/password`).**
  - Frame and structure like T14's pages: `StaffFrame`, `h1` `staff.passwordTitle`, Suspense, and
    `connection()` before any Supabase call.
  - On the server: `getUser()`, then `auth.mfa.listFactors()` (verified `totp`), then
    `decidePasswordAccess`. `sign-in` → `/{locale}/staff/sign-in`. `refused` → sign out, then
    `?error=refused`. `mfa` → `/{locale}/staff/mfa`.
  - The form is a client component in the zone (like `SignInForm.tsx`). It has two fields, new
    password and confirmation, both `type="password"` and `autocomplete="new-password"`, each with a
    label above and a hint below linked by `aria-describedby` (`DESIGN_SYSTEM.md` §9.2–§9.4).
  - Server action `setStaffPassword(locale, previous, formData)` in `actions.ts`:
    - it runs the same access decision first;
    - `checkNewPassword` → `{ error: "mismatch" }`;
    - `auth.updateUser({ password })` error → `{ error: "password" }`, one generic message;
    - success → redirect to `/{locale}/staff/mfa`.

    `StaffFormState["error"]` gains `"mismatch" | "password"`. Never echo or log a password.
- **S4 — Sign-in page.** `?error=link` shows `staff.errorLink`, in the same `role="status"` pattern
  as `?error=refused`. Change nothing else on T14's pages.
- **S5 — Catalogue.** Add exactly these 9 keys under `staff` in `src/i18n/messages/ar.json` and
  `en.json`, which gives 46 + 9 = 55 keys per locale:
  `passwordTitle`, `newPasswordLabel`, `newPasswordHint`, `confirmPasswordLabel`,
  `confirmPasswordHint`, `passwordSubmit`, `errorMismatch`, `errorPassword`, `errorLink`.
  The copy is short, with the same meaning in both languages. `errorLink` tells the staff member to
  ask the library for a new invitation. No copy names which check failed.
- **S6 — Local auth and template.**
  - `supabase/config.toml` `[auth]`: set `site_url = "http://127.0.0.1:3200"` and
    `additional_redirect_urls = ["http://127.0.0.1:3200"]`. This is the e2e server in
    `playwright.config.ts`.
  - Uncomment `[auth.email.template.invite]`, with a short bilingual `subject` and
    `content_path = "./supabase/templates/invite.html"`. Change no other line.
  - `supabase/templates/invite.html` is minimal HTML: one Arabic paragraph, one English paragraph, and
    one link whose `href` is exactly
    `{{ .SiteURL }}/ar/staff/auth/confirm?token_hash={{ .TokenHash }}&type=invite`
    (`DATA_MODEL.md` §5, `I18N_MODEL.md` §7). No image, no tracker, no third-party URL, and no other
    template variable that carries a token (`{{ .Token }}`, `{{ .ConfirmationURL }}`).
  - Apply both once: `supabase stop --no-backup`, then `node scripts/devos/supabase.mjs start`. The
    stack rebuilds from the migrations and the seed, and the runner reuses it. Then
    `docker exec supabase_auth_devos-pilot printenv GOTRUE_SITE_URL` prints `http://127.0.0.1:3200`.
    Never run `supabase db reset`.
- **S7 — Tests.**
  - **Unit:** `parseInviteLink` (invite accepted; recovery, signup, magiclink, a missing type and a
    missing or empty token refused); the four `decidePasswordAccess` outcomes; `checkNewPassword`.
  - **E2E `e2e/staff-invite.spec.ts` (serial).**

      globally from a parallel worker.
    - Admin calls go through `createClient(NEXT_PUBLIC_SUPABASE_URL, SUPABASE_SECRET_KEY,
      { auth: { persistSession: false, autoRefreshToken: false } })`, in the test process only.
    - Addresses are `invite-<run id>-<n>@example.com`. The mail comes from Mailpit:
      `GET ${SUPABASE_MAIL_URL}/api/v1/search?query=to:<address>` (poll up to 10 s), then
      `GET /api/v1/message/{ID}`. Take the link from the HTML body and decode `&amp;`.
    - **(a) Invitation to the home.**
      1. `auth.admin.inviteUserByEmail`, then grant the claim with
         `auth.admin.updateUserById(id, { app_metadata: { staff: true } })` before the link is opened
         (`DATA_MODEL.md` §5 steps 1–3).
      2. Open the link: the confirm response has `cache-control` containing `no-store`, and the page

      3. Different passwords show `staff.errorMismatch`. Save screenshots

         the language switch).
      4. Matching passwords lead to `/ar/staff/mfa`. Enrol with a TOTP code computed with
         `node:crypto`, and reach `/ar/staff` with the email in `<bdi>`.
      5. Sign out. Sign in with the new password, which shows `/mfa` with the code field only. Then
         `/ar/staff/password` redirects to `/ar/staff/mfa`. Enter the code to reach `/ar/staff`.
    - **(b)** Opening (a)'s link again, in a fresh context, ends at `/ar/staff/sign-in?error=link`
      with `staff.errorLink`, and `/ar/staff` then redirects to sign-in.
    - **(c)** An invited account without the claim ends at `?error=refused`, with no session after
      it.
    - **(d)** `request.get` with `maxRedirects: 0` on `/ar/staff/auth/confirm?token_hash=x&type=recovery`
      and on `/ar/staff/auth/confirm?type=invite` answers a 3xx whose `location` ends with
      `/ar/staff/sign-in?error=link`, and has no `set-cookie`.
    - **(e)** An anonymous `/ar/staff/password` ends at `/ar/staff/sign-in`.
    - **`afterAll`** deletes every account the spec invited (`auth.admin.deleteUser`) and their
      Mailpit messages (`DELETE ${SUPABASE_MAIL_URL}/api/v1/messages` with `{"IDs":[…]}`), so the
      stack is left as the spec found it.
