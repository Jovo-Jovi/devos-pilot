#### Steps

- **S1 — Staff gate (`src/lib/supabase/staff.ts`, `import "server-only"`).** One function,
  `requireStaff(locale)`, built on `createStaffServerClient()`. It reads the user with `getUser()` (never
  trust `getSession()` alone) and the assurance level with
  `auth.mfa.getAuthenticatorAssuranceLevel()`. Outcomes, in this order: no user → `redirect` to
  `/{locale}/staff/sign-in`; `app_metadata.staff` is not JSON `true` → sign out, then redirect to sign-in
  with `?error=refused`; level not `aal2` → redirect to `/{locale}/staff/mfa`; otherwise return a
  `StaffMember` (`{ id, email }`). Name types without any forbidden bare noun (`GLOSSARY.md` §3). Pure
  decision logic is separated from the client calls so it is unit-tested (S9).
- **S2 — Proxy (`src/proxy.ts`).** Refreshes the session with `@supabase/ssr` and writes the refreshed
  cookies on the response. `config.matcher` is exactly `["/(ar|en)/staff/:path*"]`. It sets no cookie
  and runs no code on any other URL.
- **S3 — Sign-in (`/[locale]/staff/sign-in`).** Email and password form posting to a server action;
  `signInWithPassword`. Failure shows one generic localised message (no hint which field was wrong).
  Success: redirect to `/mfa` (the gate then decides). `autocomplete` attributes set, no password echoed.
  `?error=refused` shows a localised refusal message.
- **S4 — MFA (`/[locale]/staff/mfa`).** No factor yet: a server action enrols (`mfa.enroll`, `totp`),
  the page shows the QR image (the SVG data URL) and the secret, the secret inside `<Bidi>`, then a code
  field. Verified factor present: a code field only. The action runs `challenge` + `verify`; success
  ends at AAL2 and redirects to `/{locale}/staff`. A wrong code shows a generic localised message. An
  unverified enrolment is removed before a new one is made. Requires a session (no user → sign-in).
- **S5 — Staff home (`/[locale]/staff`).** Calls `requireStaff`; shows a localised heading, the email,
  and a sign-out form (server action `signOut`, then redirect to sign-in). It is `noindex` and
  dynamic; it must not make any public route dynamic.
- **S6 — Headers.** In `next.config.ts` add a second `headers()` entry, `source: "/:locale/staff/:path*"`,
  placed after the baseline entry, setting only `Content-Security-Policy`: the baseline value with
  `form-action 'self'` replacing `form-action 'none'`, every other directive unchanged
  (`SECURITY_MODEL.md` §2a). Export what the test needs. Extend `src/security/headers.test.ts`: the
  public entry still has `form-action 'none'`; the staff entry differs from it only in that directive.
- **S7 — Catalogue.** Add `staff.*` keys to `src/i18n/messages/ar.json` and `en.json`, identical key
  sets. Pages compose `DESIGN_SYSTEM.md` §9, logical properties only, no raw colours, no hard-coded
  locale, Latin runs (email, secret, code) inside `<Bidi>`. Any staff-page copy comes from the catalogue.
- **S8 — Local auth and seed.**
  - `supabase/config.toml`: under `[auth.email]` change exactly `enable_signup = false` to
    `enable_signup = true` and replace its comment with one line saying that in the CLI this key turns the
    email provider (password sign-in) on, while sign-up stays off for every provider through
    `[auth] enable_signup = false`. Change no other line; `[auth] enable_signup = false` stays.
  - `supabase/seed.sql`: three synthetic accounts on `example.com` in `auth.users` and
    `auth.identities` (provider `email`, `identity_data` with `sub` and `email`). Password hash computed
    in SQL with `extensions.crypt(<test password>, extensions.gen_salt('bf'))`; `email_confirmed_at`
    set; `aud` and `role` `authenticated`; the token text columns (`confirmation_token`,
    `recovery_token`, `email_change_token_new`, `email_change`) set to `''`, not null. (a) staff
