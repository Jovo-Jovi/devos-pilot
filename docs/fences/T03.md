#### Steps

- **S1 — Schema and parsers.** Create `src/content/schema.ts`. Write the validation by hand. Do
  **not** add zod or any other package. It exports:
  - types `LibraryProfile`, `OpeningSlot` (`noteAr?`, `noteEn?` optional) and `LibraryNotice`
    (`status: "published" | "draft"`), with exactly the fields of `docs/CONTENT_MODEL.md` §2;
  - `parseLibraryProfile(raw: unknown): LibraryProfile`,
    `parseOpeningSlots(raw: unknown): OpeningSlot[]`,
    `parseLibraryNotices(raw: unknown): LibraryNotice[]`.
  Each parser throws an `Error` whose message starts with the file path (for example
  `content/opening-slots.json: [6].closesAt ...`). It must reject all of the following:
  a wrong top-level shape (object vs array);
  a missing or non-string required field; an empty string in a required field; an unknown field;
  a `phone` not matching E.164 `^\+[1-9]\d{1,14}$`; an `id` not kebab-case
  (`^[a-z0-9]+(-[a-z0-9]+)*$`) or duplicated within its file; `dayOfWeek` not an integer 0–6;
  `opensAt`/`closesAt` not 24h `HH:MM` (`^([01]\d|2[0-3]):[0-5]\d$`) or `opensAt >= closesAt`;
  exactly one of `noteAr`/`noteEn` present; `status` other than `published`/`draft`;
  `publishedOn` not `^\d{4}-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])$`.
- **S2 — Day ordering.** Create `src/content/order.ts` exporting
  `orderOpeningSlots(slots: readonly OpeningSlot[]): OpeningSlot[]`. It returns a **new** array
  ordered by `dayOfWeek` ascending (0 = Sunday first, per CONTENT_MODEL §2), with ties ordered by
  `opensAt` ascending. It never mutates its input. With the signed content the id order is
  `sun, mon, tue, wed, thu, sat-morning, sat-evening`.
- **S3 — Loader.** Create `src/content/library-content.ts`. It imports the three files with
  relative JSON imports (`../../content/library-profile.json`, `../../content/opening-slots.json`,
  `../../content/library-notices.json`), parses each at module scope, and exports
  `libraryProfile`, `openingSlots` (already passed through `orderOpeningSlots`) and
  `libraryNotices` (validated, unfiltered: T04 adds the published-only selector). Invalid content
  must throw during `next build` (CONTENT_MODEL §4). Never catch the error into a page.
- **S4 — Components.** Create these files. Each is a server component with typed props, with no
  `"use client"`, no hook and no interface-text literal (strings come from the catalogue via
  `getMessages`, and content text from the bilingual pair for the locale):
  - `src/components/Bidi.tsx`: `Bidi({ children })` renders `<bdi>{children}</bdi>` and nothing else.
  - `src/components/PendingState.tsx`: renders the given catalogue string in a `<p>` styled with
    `--color-pending`. No icon.
  - `src/components/LocaleSwitch.tsx`: props `locale`, `path` (the part after the locale, `""` on
    the home) and `label`. It renders a `next/link` `Link` to `/${other}${path}`, where `other` is the
    locale in `locales` that is not `locale`, with `hrefLang={other}` and `lang={other}`. The label
    is `nav.switchTo`.
  - `src/components/SiteHeader.tsx`: a `<header>` holding the library name (`nameAr`/`nameEn`), then
    a `<nav>` holding `Link`s to `/${locale}` (`nav.home`) and `/${locale}/notices` (`nav.notices`; that route
    returns 404 until T04 lands it, which is expected), then `LocaleSwitch` at the inline end.
  - `src/components/OpeningHours.tsx`: a `<table>` with one `<tr>` per slot in the given order:
    `<th scope="row">` day name from catalogue `days["0".."6"]`, a `<td>` holding
    `<Bidi>{`${opensAt}–${closesAt}`}</Bidi>` (one template string, en dash U+2013, so the times
    form a single text node), and a `<td>` with the note for the locale, empty when absent.
  - `src/components/SiteFooter.tsx`: a `<footer>` showing `footer.address` and the address for the
    locale, then `footer.phone` and `<Bidi>{libraryProfile.phone}</Bidi>`. The phone stays plain
    text: no `tel:` link.
- **S5 — Home page.** Rewrite `src/app/[locale]/page.tsx` (keep `await params` and the
  `notFound()` guard) to render, in order: `SiteHeader` (with `path=""`), then `<main>` holding the
  `h1` library name for the locale, the `p` `site.tagline`, and a `<section>` with `h2`
  `section.hours` followed by `OpeningHours` when `openingSlots.length > 0`, else
  `PendingState` with `state.pendingHours`. Then `SiteFooter`. Do not render a latest-notices
  region or the "all notices" link (T04). Do not change `layout.tsx` or `global-not-found.tsx`.
  The catalogue key is `state.pendingHours` (the catalogue is authoritative here. DESIGN_SYSTEM
  §3's `state.pending.hours` is a known doc correction, so do not edit the catalogues).
- **S6 — Style.** Add rules to `src/styles/global.css` only. Use tokens only, logical properties
  only, and no raw colour or px value (a `1px` hairline is allowed). Content column:

  Section gap `var(--space-7)`. `h1` `var(--text-5)` in `--color-ink`. Tagline `var(--text-3)` in
  `--color-ink-muted`. Header and footer separated by a `1px solid var(--color-line)` border on the
  block axis. The header's nav sits at the inline end (flex with `justify-content: space-between`).
  Table cells use `text-align: start`. Do not restyle anything else.
