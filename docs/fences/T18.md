### Prompt (canonical)

database with no rebuild: an invited account sets its password and enrols TOTP, publishes a notice

period; the REST API, called from the test process with the publishable key, refuses every read of
a draft and every write without the staff claim at AAL2. The public pages stay `○`, cookieless and
formless. The task writes no application code. Its report ends with the production checklist the
human runs after the gate merge (OD-10 §10, §11).

#### Steps

- **S1 — Spec `e2e/staff-zone.spec.ts`** (`test.describe.configure({ mode: "serial" })`, one shared
  staff context as `e2e/staff-hours.spec.ts`; public checks in fresh anonymous contexts). Reuse the
  helpers of the existing specs by copying them into this file (`totp`, `currentTotp`, the
  secret-key `adminClient`, the mail-catcher reads); do not import from or change another spec.
  Synthetic data only: `zone-<run id>@example.com`, run-id titles and notes.
  - (a) **Invitation.** `inviteUserByEmail` + the staff claim (as `staff-invite.spec.ts`), follow the
    mailed link, set the password, enrol TOTP, reach `/ar/staff`.
  - (b) **Draft stays private.** Create a notice (both languages, `publishedOn` after every date in
    `content/library-notices.json`). A publishable-key client with no session runs
    `select id from library_notices where status = 'draft'` and also selects the new id: both
    return `[]` with no error.
  - (c) **Publish.** Publish it; then anonymous `/ar/notices` and `/en/notices` show the titles, and
    `/ar` and `/en` show it among the latest three. No rebuild between steps.
  - (d) **Overlap probe (T17-a1 carry-forward).** Click unpublish while, at the same time, five
    anonymous contexts load `/ar` and `/en` (`Promise.all`). After the redirect to
    `?done=unpublished`, a new anonymous context loads `/ar`, `/en`, `/ar/notices`, `/en/notices`:
    none shows the title. Do not weaken, retry or skip this test to make it pass.
  - (e) **REST refusals** (publishable key, test process). For each of: no session; seeded
    `visitor-account@example.com` (no claim); seeded `staff-totp@example.com` signed in with the
    password only (AAL1) — an `insert` into `library_notices` and into `opening_slots` returns an
    error; an `update` of `library_notices` (`id` of a seeded published row) and of
    `opening_slots` (`tue`), and a `delete` of `opening_slots` (`tue`), each return an error or zero
    rows. Then the secret-key client confirms those rows are unchanged. Sign each session out.
  - (f) **Hours.** In the UI change `tue` closes to `20:00`; anonymous `/en` and `/ar` contain
    `09:00–20:00`; change it back to `21:00`; `09:00–20:00` is gone.
  - (g) **Public responses.** For `/ar`, `/en`, `/ar/notices`, `/en/notices`: status 200, no
    `set-cookie`, CSP `form-action 'none'`, and the HTML has no `<form`, `<input`, `<textarea` or
    `<select`.
  - `afterAll` (secret-key client): set the notice to `draft` and delete it; set `tue` back to day 2,
    `09:00`–`21:00`, null notes; delete every `opening_slots` row whose id is not in
    `content/opening-slots.json`; delete the invited user and its mail. The tables are left as P5.
- **S2 — `playwright.config.ts`.** Change only the two patterns: `chromium` `testIgnore` and
